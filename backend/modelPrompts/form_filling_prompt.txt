You will be given:

1. A FORM STRUCTURE (JSON format)
2. EXTRACTED DATA from multiple identity documents (JSON format)

Your task is to fill the form using the provided data, with **controlled and logical inference where appropriate**.

---

IMPORTANT RULES:

1. DO NOT hallucinate or invent completely new information.
2. Use ONLY the provided data, but you MAY perform **light inference and structuring** when the data is clearly present but unstructured.

---

ALLOWED INFERENCE (IMPORTANT):

3. You MAY:

   * Split a full address into components (state, city, pincode, etc.) if clearly identifiable
   * Normalize text (case, spacing, formatting)
   * Extract parts from combined fields (e.g., "Pune Maharashtra-411001" → city: Pune, state: Maharashtra, pincode: 411001)
   * Use common sense parsing for structured fields

4. You MUST NOT:

   * Guess missing values
   * Assume unknown fields
   * Fill data that is not present at all

---

FIELD RULES:

5. If a field is:

   * Not present
   * Empty
   * Unclear
   * Conflicting across documents

   → Set its value to "$"

   * Use priority:
     Aadhaar > Passport > Driving License > PAN
   * If conflict → "$"

---

SPECIAL HANDLING:

7. Address fields:

   * Try to extract meaningful components from full address string
   * Fill fields ONLY if clearly identifiable

     "Pune Maharashtra-411001"
     →
     city: Pune
     state: Maharashtra
     pincode: 411001

8. Documents submitted:

   * Infer document type from available data
   * Example:
     If Aadhaar present → proof_of_identity = "Aadhaar"
     If address present → proof_of_address = "Aadhaar"
     If DOB present → proof_of_dob = "Aadhaar/PAN/Passport" (based on source)

9. update_type:

   * Set "yes" ONLY if corresponding field exists in extracted data
   * Otherwise "$"

---

OUTPUT RULES:

10. Keep JSON structure EXACTLY same as input form
11. Do NOT add/remove fields
12. Return ONLY valid JSON
13. No explanation, no markdown, no comments

FORM STRUCTURE:
{form_structure}

{extracted_data}
